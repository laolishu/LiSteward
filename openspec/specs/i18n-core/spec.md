# 规范增量：i18n-core（国际化核心基础设施）

## 目的

建立应用国际化的基础设施，包括 vue-i18n 集成、翻译资源和后端语言管理。该规范旨在为应用提供可靠的多语言支持，确保在不同地区和语言偏好下，用户界面文本一致、可维护，并降低本地化工作的长期成本。

## 需求

### 需求：安装和配置 vue-i18n 库
应用必须在前端项目中集成 vue-i18n，作为国际化方案的基础。

#### 场景：初始化应用
当应用启动时，i18n 库必须自动初始化，加载对应语言的翻译资源。

### 需求：创建中英文翻译资源文件
应用必须建立翻译资源库，支持应用所有界面文本的多语言显示。

#### 场景：应用显示文本
所有用户可见的文本（菜单、按钮、标签、提示等）必须从翻译资源中获取，支持中英文切换。

#### 场景：引入新功能
当引入新功能时，应同时提供中英文翻译资源。

### 需求：后端提供系统语言检测
后端必须通过 Windows API 获取系统语言环境。

#### 场景：自动语言选择
应用启动时必须自动检测系统语言（zh-CN 或 en-US），作为默认语言选择。

### 需求：后端配置中添加语言设置存储
应用必须在应用配置中添加用户语言偏好字段，实现持久化存储。

#### 场景：用户修改语言
用户在应用中修改语言设置后，该偏好必须被保存到配置文件，下次启动时使用该语言。

#### 场景：优先级处理
优先级顺序：用户设置 > 系统语言 > 默认中文（zh-CN）

### 需求：暴露 Wails 绑定接口
应用必须在 app.go 中暴露语言相关的 Wails 接口，供前端调用。

#### 场景：前端获取系统语言
前端必须能调用 `GetSystemLanguage()` 获取 Windows 系统语言。

#### 场景：前端获取用户语言偏好
前端必须能调用 `GetUserLanguagePreference()` 获取用户已保存的语言选择。

#### 场景：前端保存用户语言偏好
前端必须能调用 `SetUserLanguagePreference(lang)` 保存用户语言选择。

### 需求：前端初始化逻辑
应用启动时必须自动完成语言初始化和加载。

#### 场景：冷启动
应用第一次启动时，必须检查本地存储是否有语言偏好：
- 有 → 使用保存的语言
- 无 → 调用后端获取系统语言
- 系统语言获取失败 → 使用默认中文（zh-CN）

#### 场景：热启动
应用已运行，使用当前已初始化的语言。

### 需求：应用启动流程中的语言初始化
应用必须在 app.go 的 startup() 方法中添加语言初始化逻辑。

#### 场景：应用启动
启动时如果配置中没有语言设置，必须自动检测系统语言并保存。

## 修改需求

无

## 验收标准

- [ ] vue-i18n 已集成到项目中
- [ ] 翻译资源文件包含所有必要的应用界面文本
- [ ] 中文和英文翻译文本完整对应
- [ ] 后端能正确检测 Windows 系统语言
- [ ] 应用配置支持语言字段的读写
- [ ] Wails 绑定接口实现正确
- [ ] 应用启动时正确初始化语言
- [ ] localStorage 中正确保存语言偏好
- [ ] 前后端语言设置保持同步
