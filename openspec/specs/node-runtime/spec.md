## 需求
### 需求：检测并安装 nvm
应用必须能够检测主机上是否已安装 nvm，并在用户确认或自动模式下安装最新稳定版本的 nvm。

#### 场景：检测 nvm
- **当** 用户打开 Node 管理页面
- **那么** 应调用后端接口检测 nvm 是否安装并显示结果（已安装/未安装/错误）

#### 场景：自动安装 nvm
- **当** nvm 未安装且用户点击“安装”并确认
- **那么** 后端应尝试安装最新稳定版 nvm，并在完成或失败时返回详细结果

### 需求：列出本地已安装的 Node 版本
应用必须能够列出通过 nvm 管理的本地 Node 版本。

#### 场景：列出版本
- **当** 用户请求列出已安装版本
- **那么** 后端返回已安装版本列表及当前使用的版本标识

### 需求：安装/卸载 Node 版本
应用必须支持安装与卸载指定的 Node 版本。

#### 场景：安装版本
- **当** 用户选择一个远程可用版本并点击“安装”
- **那么** 后端启动安装任务并在完成后更新已安装列表

#### 场景：卸载版本
- **当** 用户选择已安装的版本并点击“卸载”
- **那么** 后端卸载该版本并在完成后更新已安装列表

### 需求：切换当前 Node 版本
应用必须支持将当前环境的 Node 版本切换为指定版本（通过 nvm 管理）。

#### 场景：切换版本
- **当** 用户在版本列表点击“使用”指定版本
- **那么** 后端将该版本设为当前使用版本并确认切换成功

### 需求：配置 nvm 存储目录
应用必须提供设置 `NVM_DIR` 的能力并将其持久化到用户配置。后端在读取/写入时应验证目录有效性。

#### 场景：修改 NVM_DIR
- **当** 用户在 UI 中输入新的 nvm 存储目录并保存
- **那么** 后端验证目录并保存到 `user.json`，如果目录不存在则尝试创建或返回相应错误
