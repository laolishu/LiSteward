# Hosts 文件管理规范

## 目的
定义 Hosts 文件管理系统的完整需求，包括文件读取、解析、编辑、禁用/启用条目、备份和恢复等核心功能。
## 需求
系统必须提供完整的 Hosts 文件管理能力，支持Windows系统的Hosts文件标准操作。

### 需求：方案重命名 ✓ 已实现
系统必须支持对已保存的配置方案进行重命名，无需重新创建或丢失数据。

#### 场景：成功重命名方案
- **当** 用户在方案卡片上点击编辑/重命名按钮
- **那么** 显示重命名对话框，包含当前方案名称和输入框
- **并且** 用户输入新名称如 `生产环境`
- **并且** 点击"确定"确认
- **那么** 系统重命名方案文件
- **并且** 方案列表刷新，显示新名称
- **并且** 显示成功提示："方案已重命名为 '生产环境'"
- **✓ 已实现**：所有步骤已完成

#### 场景：新名称为空或非法
- **当** 用户输入空名称或仅包含空格
- **那么** 显示错误提示："方案名称不能为空"
- **并且** 对话框保持打开，用户可重新输入
- **✓ 已实现**：前端和后端验证到位

#### 场景：新名称与原名称相同
- **当** 用户输入与原方案相同的名称
- **那么** 显示提示："新名称与原名称相同，无需修改"
- **并且** 关闭对话框，不执行重命名
- **✓ 已实现**：后端返回 nil，前端作为无操作处理

#### 场景：新名称已存在
- **当** 用户输入的名称与现有方案重复
- **那么** 系统允许覆盖现有方案
- **并且** 使用新内容覆盖现有方案
- **✓ 已实现**：后端自动删除目标方案后重命名

#### 场景：取消重命名
- **当** 用户在重命名对话框中点击"取消"按钮
- **那么** 对话框关闭
- **并且** 方案名称保持不变
- **✓ 已实现**：cancelRenameProfile 方法清除状态

#### 场景：重命名不存在的方案
- **当** 用户尝试重命名已被删除的方案（并发操作）
- **那么** 显示错误提示："方案不存在或已删除"
- **并且** 刷新方案列表以反映最新状态
- **✓ 已实现**：后端检查文件存在性

#### 场景：重命名失败处理
- **当** 重命名操作失败（如文件权限问题）
- **那么** 显示错误提示，包含具体错误信息
- **并且** 原方案名称保持不变
- **并且** 对话框保持打开以便重试
- **✓ 已实现**：后端在失败时尝试恢复原文件

### 需求：缓存模式编辑
系统必须支持在内存中缓存条目编辑，延迟文件写入。

#### 场景：添加条目进缓存
- **当** 用户填写 IP 和域名并点击"+ 添加"按钮
- **那么** 条目添加到界面列表（内存缓存）
- **并且** 系统不立即写入 Hosts 文件
- **并且** "应用"按钮变为可见（或从禁用变为启用）
- **并且** 显示"存在未保存更改"提示

#### 场景：编辑条目进缓存
- **当** 用户修改某条目内容并点击"保存"
- **那么** 条目在界面中立即更新（内存缓存）
- **并且** 系统不立即写入 Hosts 文件
- **并且** "应用"按钮变为可见

#### 场景：删除条目进缓存
- **当** 用户删除某条目并确认
- **那么** 条目从界面中移除（内存缓存）
- **并且** 系统不立即写入 Hosts 文件
- **并且** "应用"按钮变为可见

#### 场景：切换条目启用状态
- **当** 用户点击条目的启用/禁用开关
- **那么** 条目状态在界面中立即反映（纯 UI 反馈）
- **并且** "应用"按钮变为可见

#### 场景：刷新丢弃未保存更改
- **当** 用户修改了条目但未点击"应用"
- **并且** 点击"刷新"按钮
- **那么** 系统显示确认对话框："将放弃未保存的更改，是否继续？"
- **并且** 用户确认后，从 Hosts 文件重新加载条目
- **并且** 所有内存中的未保存更改被丢弃
- **并且** "应用"按钮隐藏（或变为禁用）

系统必须提供显式的"应用"操作将缓存的更改写入 Hosts 文件。

#### 场景：应用更改成功
- **当** 用户修改了一个或多个条目
- **并且** 点击"应用"按钮
- **那么** 系统将内存中的所有条目写入 Hosts 文件

- **当** 文件保存成功但恢复只读属性失败
- **那么** 显示警告提示："文件已保存，但恢复只读属性失败"

## 新增需求

### 需求：Hosts 文件读取
系统必须能够读取 Windows 系统 Hosts 文件并解析为结构化数据。

#### 场景：成功读取 Hosts 文件
- **当** 用户打开 Hosts 管理模块
- **那么** 系统读取 `C:\Windows\System32\drivers\etc\hosts` 文件
- **并且** 解析文件内容为条目列表
- **并且** 在界面中展示所有条目

#### 场景：解析启用的条目
- **当** Hosts 文件包含行 `127.0.0.1 localhost # 本地回环`
- **那么** 解析为：IP=`127.0.0.1`, 域名=`localhost`, 注释=`本地回环`, 启用=`true`

#### 场景：解析禁用的条目
- **当** Hosts 文件包含行 `# 192.168.1.100 dev.local # 开发服务器`
- **那么** 解析为：IP=`192.168.1.100`, 域名=`dev.local`, 注释=`开发服务器`, 启用=`false`

#### 场景：忽略空行和纯注释
- **当** Hosts 文件包含空行或纯注释行
- **那么** 系统忽略这些行，不创建条目

#### 场景：权限不足
- **当** 应用未以 Administrator 权限运行
- **那么** 显示错误提示："需要管理员权限才能访问 Hosts 文件"
- **并且** 提供"以管理员身份重启"选项

---

### 需求：Hosts 文件写入
系统必须能够将修改后的条目写入 Hosts 文件。

#### 场景：成功写入 Hosts 文件
- **当** 用户点击"保存"按钮
- **那么** 系统自动备份当前 Hosts 文件
- **并且** 将条目列表转换为标准 Hosts 文件格式
- **并且** 写入到 `C:\Windows\System32\drivers\etc\hosts`
- **并且** 显示成功提示

#### 场景：生成启用条目
- **当** 条目为：IP=`192.168.1.100`, 域名=`api.dev.local`, 注释=`API服务`, 启用=`true`
- **那么** 生成行：`192.168.1.100    api.dev.local    # API服务`

#### 场景：生成禁用条目
- **当** 条目为：IP=`10.0.0.5`, 域名=`old.server.com`, 启用=`false`
- **那么** 生成行：`# 10.0.0.5    old.server.com`

#### 场景：写入失败处理
- **当** 写入 Hosts 文件失败（如被其他程序锁定）
- **那么** 显示错误提示："Hosts 文件被占用，请关闭防病毒软件或其他相关程序后重试"
- **并且** 提供"重试"按钮

---

### 需求：条目验证
系统必须验证 IP 地址和域名格式，防止无效配置。

#### 场景：验证有效的 IPv4 地址
- **当** 用户输入 IP 地址 `192.168.1.1`
- **那么** 验证通过，允许保存

#### 场景：拒绝无效的 IPv4 地址
- **当** 用户输入 IP 地址 `999.999.999.999`
- **那么** 显示错误："无效的 IPv4 地址"
- **并且** 禁止保存

#### 场景：验证有效的域名
- **当** 用户输入域名 `api.example.com`
- **那么** 验证通过

#### 场景：支持 localhost
- **当** 用户输入域名 `localhost`
- **那么** 验证通过（允许特殊域名）

#### 场景：拒绝空白域名
- **当** 用户域名字段为空
- **那么** 显示错误："域名不能为空"

## 需求
### 需求：Hosts 文件读取

系统必须能够读取 Windows 系统 Hosts 文件并解析为结构化数据。

#### 场景：成功读取 Hosts 文件

- **当** 用户打开 Hosts 管理模块
- **那么** 系统读取 `C:\Windows\System32\drivers\etc\hosts` 文件
- **并且** 解析文件内容为条目列表
- **并且** 在界面中展示所有条目

#### 场景：解析启用的条目

- **当** Hosts 文件包含行 `127.0.0.1 localhost # 本地回环`
- **那么** 解析为：IP=`127.0.0.1`, 域名=`localhost`, 注释=`本地回环`, 启用=`true`

#### 场景：解析禁用的条目

- **当** Hosts 文件包含行 `# 192.168.1.100 dev.local # 开发服务器`
- **那么** 解析为：IP=`192.168.1.100`, 域名=`dev.local`, 注释=`开发服务器`, 启用=`false`

#### 场景：忽略空行和纯注释

- **当** Hosts 文件包含空行或纯注释行
- **那么** 系统忽略这些行，不创建条目

#### 场景：权限不足

- **当** 应用未以 Administrator 权限运行
- **那么** 显示错误提示："需要管理员权限才能访问 Hosts 文件"
- **并且** 提供"以管理员身份重启"选项

---

### 需求：Hosts 文件写入

系统必须能够将修改后的条目写入 Hosts 文件。

#### 场景：成功写入 Hosts 文件

- **当** 用户点击"保存"按钮
- **那么** 系统自动备份当前 Hosts 文件
- **并且** 将条目列表转换为标准 Hosts 文件格式
- **并且** 写入到 `C:\Windows\System32\drivers\etc\hosts`
- **并且** 显示成功提示

#### 场景：生成启用条目

- **当** 条目为：IP=`192.168.1.100`, 域名=`api.dev.local`, 注释=`API服务`, 启用=`true`
- **那么** 生成行：`192.168.1.100    api.dev.local    # API服务`

#### 场景：生成禁用条目

- **当** 条目为：IP=`10.0.0.5`, 域名=`old.server.com`, 启用=`false`
- **那么** 生成行：`# 10.0.0.5    old.server.com`

#### 场景：写入失败处理

- **当** 写入 Hosts 文件失败（如被其他程序锁定）
- **那么** 显示错误提示："Hosts 文件被占用，请关闭防病毒软件或其他相关程序后重试"
- **并且** 提供"重试"按钮

### 需求：条目验证

系统必须验证 IP 地址和域名格式，防止无效配置。

#### 场景：验证有效的 IPv4 地址

- **当** 用户输入 IP 地址 `192.168.1.1`
- **那么** 验证通过，允许保存

#### 场景：拒绝无效的 IPv4 地址

- **那么** 显示错误："无效的 IPv4 地址"

#### 场景：验证有效的域名

- **当** 用户输入域名 `api.example.com`
- **那么** 验证通过

#### 场景：支持 localhost

- **当** 用户输入域名 `localhost`
- **那么** 验证通过（允许特殊域名）

#### 场景：拒绝空白域名
