# 变更：添加国际化支持

## 为什么

LiSteward 作为桌面应用，当前仅支持中文界面。在实际使用中，全球用户需要：

- **多语言支持**：满足不同语言使用者的需求（中文、英文等）
- **自动检测**：根据系统语言环境自动选择合适的界面语言
- **用户定制**：用户可以在应用内自主选择和切换语言
- **一致体验**：确保所有界面元素（菜单、对话框、表格、错误消息等）都支持国际化

当前单一语言限制了应用的市场范围，无法满足国际用户需求。

## 变更内容

### 核心功能

#### 1. 国际化基础设施

在前后端建立完整的国际化体系：

**后端：**
- 通过 Wails 绑定暴露系统语言信息
- 支持获取应用当前语言设置
- 支持设置和持久化用户语言偏好

**前端：**
- 集成 i18n 库（使用 vue-i18n 或等价方案）
- 建立完整的翻译资源文件（中文、英文）
- 实现语言切换逻辑

#### 2. 语言自动检测

应用启动时：
1. 检查用户已保存的语言偏好
2. 如果未设置，检测系统语言环境（Windows 本地化设置）
3. 默认语言：中文（zh-CN）
4. 支持语言：中文（zh-CN）、英文（en-US）

#### 3. 语言设置界面

在"设置"模块添加语言选择功能：
- 显示当前语言
- 下拉菜单选择语言（中文、英文）
- 切换语言后实时更新界面（无需重启）
- 语言偏好持久化保存

#### 4. 国际化范围

应用所有用户可见的文本都支持国际化：
- 菜单项和导航
- 表格列标题和内容
- 对话框和表单标签
- 按钮和操作提示
- 状态消息和错误提示
- 占位符文本

### 技术架构

#### 前端 I18n 方案

```
frontend/
├── src/
│   ├── i18n/
│   │   ├── index.js              # i18n 配置和初始化
│   │   ├── locales/
│   │   │   ├── zh-CN.json        # 中文翻译文本
│   │   │   └── en-US.json        # 英文翻译文本
│   │   └── messages.js           # 消息常量导出
│   ├── App.vue                   # 使用 i18n 的应用主组件
│   ├── components/               # 所有组件使用 i18n
│   └── views/                    # 所有视图使用 i18n
```

#### 后端支持

- 新增 Go 函数：`GetSystemLanguage()` - 获取 Windows 系统语言
- 新增 Go 函数：`GetUserLanguagePreference()` - 获取用户已保存的语言偏好
- 新增 Go 函数：`SetUserLanguagePreference(language string)` - 保存用户语言偏好
- 通过 config 包持久化语言设置

#### 数据持久化

在应用配置中添加：
```go
type AppConfig struct {
    // ... 其他字段
    Language string // 用户选择的语言 (zh-CN, en-US)
}
```

### 向后兼容性

- 此变更为纯增强功能，不修改现有数据格式
- 无法向后兼容涉及，现有配置文件无需升级
- 新增语言字段采用默认值处理，不影响现有应用

## 实施策略

按两个并行的规范增量分开实施：

1. **i18n-core**：建立国际化基础设施
   - 集成 i18n 库
   - 建立翻译资源
   - 后端支持语言检测和设置

2. **i18n-settings**：在设置模块添加语言切换UI
   - 创建语言设置视图
   - 实现实时语言切换

## 验收标准

- [ ] 应用启动时自动检测系统语言
- [ ] 所有菜单、按钮、标签都支持中英文切换
- [ ] 在设置模块可以选择语言
- [ ] 语言选择后实时更新，无需重启
- [ ] 用户语言偏好持久化保存
- [ ] 系统语言和应用语言完全分离独立
