# UI 图标规范

## 目的
定义应用中所有 UI 图标的存储、格式、样式和使用规范，确保一致的视觉体验。

## 新增需求

### 需求：SVG 图标存储标准
应用必须使用 SVG 格式存储所有 UI 图标，集中管理在 `frontend/public/images/` 目录中。

#### 场景：菜单图标存储
- **给定** 应用需要为左侧导航菜单提供图标
- **当** 图标需要添加到应用
- **那么** 图标必须存储为 SVG 文件格式
- **并且** 文件名遵循 `menu-<name>.svg` 命名规则
- **并且** 存储位置为 `frontend/public/images/menu-<name>.svg`
- **并且** 文件大小应不超过 1KB

#### 场景：工具栏操作图标存储
- **给定** 应用需要为各工具栏按钮提供图标
- **当** 操作按钮图标需要添加
- **那么** 图标必须存储为 SVG 文件格式
- **并且** 文件名遵循 `toolbar-<action>.svg` 命名规则
- **并且** 存储位置为 `frontend/public/images/toolbar-<action>.svg`
- **并且** 文件大小应不超过 1KB

#### 场景：消息状态图标存储
- **给定** 应用需要为消息状态提供反馈图标
- **当** 消息图标需要添加
- **那么** 图标必须存储为 SVG 文件格式
- **并且** 文件名遵循 `message-<status>.svg` 命名规则
- **并且** 存储位置为 `frontend/public/images/message-<status>.svg`

### 需求：SVG 图标颜色规范
所有 SVG 图标必须遵循统一的配色方案，以确保视觉一致性。

#### 场景：中性操作图标颜色
- **给定** 应用的菜单和通用操作需要图标
- **当** 菜单图标被创建或更新
- **那么** 菜单图标必须使用中性灰色 `#24292e` 作为主色
- **并且** 菜单图标在悬停时应显示为 `#586069`（更浅的灰色）
- **并且** 图标的线条宽度应为 1.4-2px，保证清晰度

#### 场景：确定/成功操作图标颜色
- **给定** 应用需要表示确定、应用、成功等操作
- **当** 这些操作图标被创建
- **那么** 图标必须使用绿色 `#10B981`（Tailwind emerald-500）
- **并且** 不同操作状态下需要调整透明度或亮度
- **并且** 用户能够清晰地识别这是积极的操作

#### 场景：删除/错误操作图标颜色
- **给定** 应用需要表示删除、错误、警告等操作
- **当** 这些操作图标被创建
- **那么** 图标必须使用红色 `#EF4444`（Tailwind red-500）
- **并且** 用户能够清晰地识别这是消极的操作
- **并且** 错误消息中的图标应突出显示问题

### 需求：图标组件集成
应用中的组件必须通过 `<img>` 标签或 URL 引用正确使用 SVG 图标。

#### 场景：菜单组件使用 SVG 图标
- **给定** Sidebar 组件显示导航菜单项
- **当** 菜单项呈现
- **那么** 菜单项必须显示相应的 SVG 图标
- **并且** 图标通过 `<img src="/images/menu-<name>.svg" />` 标签引用
- **并且** 图标大小应为 18x18px
- **并且** 图标应在菜单项文本之前显示
- **并且** 悬停菜单项时图标应响应样式变化

#### 场景：工具栏按钮使用 SVG 图标
- **给定** HostsManager 等页面的工具栏包含操作按钮
- **当** 按钮被渲染
- **那么** 按钮必须显示相应的 SVG 图标
- **并且** 图标通过 `<img src="/images/toolbar-<action>.svg" />` 标签引用
- **并且** 图标大小应为 16x16px
- **并且** 图标应清晰可见且易于点击

#### 场景：消息反馈使用 SVG 图标
- **给定** 应用显示用户操作结果消息
- **当** 成功或错误消息出现
- **那么** 消息必须包含状态图标
- **并且** 成功消息使用 `message-success.svg` 图标
- **并且** 错误消息使用 `message-error.svg` 图标
- **并且** 图标应采用相应的颜色（绿色/红色）

### 需求：图标可访问性和可用性
所有图标必须满足可访问性标准，确保用户能够理解其含义。

#### 场景：图标的替代文本
- **给定** 页面中使用 SVG 图标
- **当** 图标通过 `<img>` 标签显示
- **那么** `<img>` 标签必须包含 `alt` 属性
- **并且** `alt` 文本应准确描述图标的含义（例如 "hosts", "refresh", "success"）
- **并且** 屏幕阅读器用户能够理解图标的用途

#### 场景：按钮图标的标题提示
- **给定** 工具栏按钮或操作按钮包含 SVG 图标
- **当** 用户将鼠标悬停在按钮上
- **那么** 应显示 `title` 属性提示
- **并且** 提示文本应通过 i18n 本地化（例如 `$t('hosts.reload')`）
- **并且** 用户能够理解按钮的功能

### 需求：图标视觉一致性
所有应用中的 SVG 图标必须保持视觉风格的一致性。

#### 场景：图标线条风格一致
- **给定** 应用中有多个菜单和工具栏图标
- **当** 图标被显示
- **那么** 所有图标必须使用一致的线条宽度（1.4-2px）
- **并且** 所有图标应使用一致的风格（描边而非填充）
- **并且** 用户感受到统一的设计语言

#### 场景：图标尺寸标准化
- **给定** 应用中不同位置使用 SVG 图标
- **当** 图标在不同 UI 元素中使用
- **那么** 菜单图标尺寸应标准为 18x18px
- **并且** 工具栏图标尺寸应标准为 16x16px
- **并且** 消息图标尺寸应标准为 16x16px
- **并且** 不同尺寸的图标应该有相同的线条宽度比例

#### 场景：图标动画和交互反馈
- **给定** 用户与包含 SVG 图标的 UI 元素交互
- **当** 用户悬停或点击元素
- **那么** 图标应通过颜色或透明度变化提供视觉反馈
- **并且** 反馈效果应通过 CSS 实现（:hover、:active 等）
- **并且** 动画应流畅且响应迅速
