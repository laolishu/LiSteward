# Hosts 配置方案重命名功能规范

## 新增需求

### 需求：方案重命名 ✓ 已实现
系统必须支持对已保存的配置方案进行重命名，无需重新创建或丢失数据。

#### 场景：成功重命名方案
- **当** 用户在方案卡片上点击编辑/重命名按钮
- **那么** 显示重命名对话框，包含当前方案名称和输入框
- **并且** 用户输入新名称如 `生产环境`
- **并且** 点击"确定"确认
- **那么** 系统重命名方案文件
- **并且** 方案列表刷新，显示新名称
- **并且** 显示成功提示："方案已重命名为 '生产环境'"
- **✓ 已实现**：所有步骤已完成

#### 场景：新名称为空或非法
- **当** 用户输入空名称或仅包含空格
- **那么** 显示错误提示："方案名称不能为空"
- **并且** 对话框保持打开，用户可重新输入
- **✓ 已实现**：前端和后端验证到位

#### 场景：新名称与原名称相同
- **当** 用户输入与原方案相同的名称
- **那么** 显示提示："新名称与原名称相同，无需修改"
- **并且** 关闭对话框，不执行重命名
- **✓ 已实现**：后端返回 nil，前端作为无操作处理

#### 场景：新名称已存在
- **当** 用户输入的名称与现有方案重复
- **那么** 系统允许覆盖现有方案
- **并且** 使用新内容覆盖现有方案
- **✓ 已实现**：后端自动删除目标方案后重命名

#### 场景：取消重命名
- **当** 用户在重命名对话框中点击"取消"按钮
- **那么** 对话框关闭
- **并且** 方案名称保持不变
- **✓ 已实现**：cancelRenameProfile 方法清除状态

#### 场景：重命名不存在的方案
- **当** 用户尝试重命名已被删除的方案（并发操作）
- **那么** 显示错误提示："方案不存在或已删除"
- **并且** 刷新方案列表以反映最新状态
- **✓ 已实现**：后端检查文件存在性

#### 场景：重命名失败处理
- **当** 重命名操作失败（如文件权限问题）
- **那么** 显示错误提示，包含具体错误信息
- **并且** 原方案名称保持不变
- **并且** 对话框保持打开以便重试
- **✓ 已实现**：后端在失败时尝试恢复原文件
