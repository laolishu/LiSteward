# 变更：Hosts 管理缓存模式与显式保存

## 为什么
当前 Hosts 管理器在每次添加、编辑或删除条目时立即写入系统 Hosts 文件。这可能导致以下问题：
- 用户可能意外进行多个操作后才意识到需要撤销
- 频繁的文件写入增加磁盘 I/O
- 文件操作失败会中断工作流，用户无法继续编辑
- 缺乏显式"应用"机制，使工作流不够清晰

## 变更内容
- 实现**缓存模式**：所有添加、编辑、删除操作在内存中进行，不立即写入文件
- 添加**"应用"按钮**：用户显式点击时才将缓存的更改写入 Hosts 文件
- 添加**"刷新"按钮**：直接从 Hosts 文件重新加载，丢弃未保存的缓存更改
- 实现**自动权限恢复**：应用时如果 Hosts 文件为只读，先取消只读、保存、再恢复只读属性
- 增强 **UI 反馈**：显示缓存中是否有未保存的更改

## 影响
- 受影响规范：[hosts-management](../specs/hosts-management/spec.md)
- 受影响代码：
  - 前端：`frontend/src/views/HostsManager.vue`（修改自动保存逻辑）
  - 后端：`internal/hosts/service.go`（添加权限恢复逻辑）

## 相关设计决策
- **缓存作用域**：仅在前端内存中（单会话），不涉及后端缓存
- **权限处理**：后端在保存时自动处理 Hosts 文件只读属性，前端无需关心
- **用户交互**：保留"启用/禁用"的即时反馈（纯 UI 状态），但实际文件保存延迟
