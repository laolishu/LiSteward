# Hosts 文件管理缓存模式规范

## 新增需求

### 需求：缓存模式编辑
系统必须支持在内存中缓存条目编辑，延迟文件写入。

#### 场景：添加条目进缓存
- **当** 用户填写 IP 和域名并点击"+ 添加"按钮
- **那么** 条目添加到界面列表（内存缓存）
- **并且** 系统不立即写入 Hosts 文件
- **并且** "应用"按钮变为可见（或从禁用变为启用）
- **并且** 显示"存在未保存更改"提示

#### 场景：编辑条目进缓存
- **当** 用户修改某条目内容并点击"保存"
- **那么** 条目在界面中立即更新（内存缓存）
- **并且** 系统不立即写入 Hosts 文件
- **并且** "应用"按钮变为可见

#### 场景：删除条目进缓存
- **当** 用户删除某条目并确认
- **那么** 条目从界面中移除（内存缓存）
- **并且** 系统不立即写入 Hosts 文件
- **并且** "应用"按钮变为可见

#### 场景：切换条目启用状态
- **当** 用户点击条目的启用/禁用开关
- **那么** 条目状态在界面中立即反映（纯 UI 反馈）
- **并且** "应用"按钮变为可见

#### 场景：刷新丢弃未保存更改
- **当** 用户修改了条目但未点击"应用"
- **并且** 点击"刷新"按钮
- **那么** 系统显示确认对话框："将放弃未保存的更改，是否继续？"
- **并且** 用户确认后，从 Hosts 文件重新加载条目
- **并且** 所有内存中的未保存更改被丢弃
- **并且** "应用"按钮隐藏（或变为禁用）

---

### 需求：显式应用更改
系统必须提供显式的"应用"操作将缓存的更改写入 Hosts 文件。

#### 场景：应用更改成功
- **当** 用户修改了一个或多个条目
- **并且** 点击"应用"按钮
- **那么** 系统将内存中的所有条目写入 Hosts 文件
- **并且** 自动创建备份
- **并且** 显示成功提示："更改已保存"
- **并且** "应用"按钮隐藏（或变为禁用）

#### 场景：应用多个操作
- **当** 用户连续执行"添加条目"、"编辑条目"、"删除条目"
- **并且** 点击"应用"按钮
- **那么** 系统将所有操作一次性写入 Hosts 文件
- **并且** 只创建一个备份（所有操作前）

#### 场景：应用失败处理
- **当** 应用更改时 Hosts 文件被占用或其他错误发生
- **那么** 显示错误提示，包括具体错误信息
- **并且** "应用"按钮保持可见（未保存的更改仍在缓存中）
- **并且** 提供"重试"选项

---

### 需求：只读属性处理
系统必须自动处理 Hosts 文件的只读属性，应用时临时取消、保存后恢复。

#### 场景：只读文件应用成功
- **当** Hosts 文件被设置为只读
- **并且** 用户点击"应用"按钮
- **那么** 系统检测只读属性
- **并且** 临时取消只读标志
- **并且** 写入更改到文件
- **并且** 恢复原有的只读属性
- **并且** 显示成功提示

#### 场景：权限检测失败
- **当** 系统无法修改 Hosts 文件属性（如权限不足）
- **那么** 显示错误提示："无权限修改 Hosts 文件，请以管理员身份运行应用"
- **并且** 应用操作中止，缓存的更改保留

#### 场景：恢复只读属性失败
- **当** 文件保存成功但恢复只读属性失败
- **那么** 显示警告提示："文件已保存，但恢复只读属性失败"
- **并且** 缓存的更改被清空（文件保存成功）
- **并且** 建议用户手动恢复文件属性

---

### 需求：刷新操作
系统必须提供"刷新"操作直接从 Hosts 文件重新加载，丢弃未保存的更改。

#### 场景：刷新当前 Hosts 文件
- **当** 用户点击"刷新"按钮且无未保存更改
- **那么** 系统从 Hosts 文件重新加载条目列表
- **并且** 显示加载成功提示
- **并且** "应用"按钮保持隐藏

#### 场景：刷新时确认丢弃更改
- **当** 用户有未保存的更改
- **并且** 点击"刷新"按钮
- **那么** 系统显示确认对话框
- **并且** 对话框提示具体有多少条目被添加/编辑/删除
- **并且** 用户确认后执行刷新
- **并且** 所有未保存的更改丢弃，"应用"按钮隐藏

---

### 需求：缓存状态提示
系统必须向用户清晰指示缓存的存在和状态。

#### 场景：显示未保存更改指示
- **当** 用户进行了任何修改操作（添加/编辑/删除/切换启用状态）
- **那么** 工具栏或标题栏显示"●未保存的更改"提示
- **并且** "应用"按钮使用强调颜色（如红色或橙色）突出显示

#### 场景：清除更改指示
- **当** 用户点击"应用"按钮并保存成功
- **或** 用户点击"刷新"按钮并确认丢弃
- **那么** 工具栏的"未保存的更改"提示消失
- **并且** "应用"按钮隐藏或变为禁用

#### 场景：页面关闭时提醒
- **当** 用户有未保存的更改且试图关闭应用
- **那么** 系统显示提示："您有未保存的更改，确定要退出吗？"
- **并且** 提供"保存并退出"、"放弃更改"两个选项
- **（注：此场景可在 UI 实施中按需决定是否支持）**
