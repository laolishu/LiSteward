# 规范：版本和应用信息

## 新增需求

### 需求：显示应用版本信息

设置页面**必须**显示应用的基本信息，包括版本号。

#### 场景：用户查看应用版本

用户在设置页面中**应该**能看到：
- 应用名称（中文和英文）
- 当前版本号
- 版本号**必须**从 `AppConfig.Version` 字段读取

示例显示：
```
李管家 (LiSteward)
v0.1.0
```

#### 场景：版本号更新时自动同步

当应用配置文件中的版本号更新时，设置页面**必须**自动显示新的版本号，无需任何前端代码修改。

### 需求：显示官方网址

设置页面**必须**显示可点击的官方网址链接。

#### 场景：用户访问官方网站

用户在设置页面中**应该**看到官方网址，点击后**必须**在默认浏览器中打开该链接。

网址**必须**从 `AppConfig.Website` 字段读取。如果该字段为空或不存在，则**禁止**显示此项。

#### 场景：网址支持各种来源

网址**必须**支持：
- 互联网网址（https://）
- GitHub 链接
- 自定义域名

### 需求：显示作者信息

设置页面**必须**显示应用作者的信息。

#### 场景：用户了解应用作者

用户在设置页面中**应该**能看到：
- 作者名称
- 作者邮箱（如果可用）

作者信息**必须**从 `AppConfig.Author` 对象读取（`Name` 和 `Email` 字段）。

#### 场景：联系作者

用户**应该**能够通过邮箱地址联系应用作者。邮箱**应该**是可点击的，点击后**必须**打开默认邮件客户端。

## 修改需求

### 需求：扩展应用配置

应用配置文件**必须**支持新的字段，以存储版本信息和联系方式。

#### 场景：配置文件包含网址和作者信息

`config/app.json` **必须**包含以下字段：

- `version`：字符串，应用版本号（例如 "0.1.0"）
- `website`：字符串，官方网址（例如 "https://example.com"）
- `author`：对象，包含 `name` 和 `email` 字段

这些字段**必须**被 `AppConfig` 结构正确解析和暴露给前端。
