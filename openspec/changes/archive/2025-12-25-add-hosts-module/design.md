# 技术设计文档

## 上下文

Hosts 文件是操作系统用于 DNS 解析的本地配置文件，开发者常用它来：
- 指向开发/测试服务器
- 屏蔽广告域名
- 绕过 DNS 缓存问题

**挑战**：
- Hosts 文件位于系统目录，需要 Administrator 权限
- 手动编辑容易出错（格式、拼写）
- 没有版本控制，误操作难以恢复
- 多环境切换繁琐

**约束**：
- 必须以 Admin 权限运行（已在项目约定中）
- Windows 系统 Hosts 路径：`C:\Windows\System32\drivers\etc\hosts`
- 兼容标准 Hosts 文件格式（IPv4/IPv6 + 域名 + 注释）

## 目标 / 非目标

### 目标
- ✅ 提供可视化的 Hosts 文件编辑界面
- ✅ 支持多方案快速切换（开发/测试/生产）
- ✅ 自动备份机制，防止数据丢失
- ✅ 验证 IP 和域名格式，防止配置错误
- ✅ 启用/禁用条目（通过注释符 `#`）

### 非目标
- ❌ 不支持 Linux/macOS（项目限定 Windows）
- ❌ 不提供远程同步功能（可在后续版本考虑）
- ❌ 不处理 DNS 缓存刷新（用户需手动运行 `ipconfig /flushdns`）

## 决策

### D1: 数据结构设计

**HostEntry 结构**（Go）：
```go
type HostEntry struct {
    IP      string `json:"ip"`       // IP 地址（IPv4 或 IPv6）
    Domain  string `json:"domain"`   // 域名
    Comment string `json:"comment"`  // 注释（可选）
    Enabled bool   `json:"enabled"`  // 是否启用
}
```

**HostsProfile 结构**（方案存储）：
```go
type HostsProfile struct {
    Name      string      `json:"name"`       // 方案名称
    Entries   []HostEntry `json:"entries"`    // Hosts 条目列表
    CreatedAt time.Time   `json:"created_at"` // 创建时间
    UpdatedAt time.Time   `json:"updated_at"` // 更新时间
}
```

**为什么这样设计**：
- `Enabled` 字段允许临时禁用条目，无需删除
- `Comment` 支持注释说明，便于维护
- 结构化数据方便前端渲染和操作
- JSON 序列化用于方案持久化

### D2: 文件操作策略

**读取流程**：
```
1. 读取 C:\Windows\System32\drivers\etc\hosts
2. 逐行解析：
   - 以 # 开头 → 注释行或禁用条目
   - 解析 IP + 域名 → 创建 HostEntry
   - 空行 → 忽略
3. 返回 []HostEntry
```

**写入流程**：
```
1. 自动备份当前 Hosts 文件
2. 生成新的 Hosts 文件内容：
   - 禁用条目：在行首添加 #
   - 启用条目：IP + TAB + Domain + COMMENT
3. 原子性写入（写入临时文件 → 重命名）
```

**考虑的替代方案**：
- ❌ 直接修改文件（风险高，无法回滚）
- ✅ 备份后写入（当前方案，安全可靠）
- ❌ 使用文件锁（Windows 系统可能会锁定 Hosts 文件）

### D3: 备份策略

**备份存储位置**：
- Windows：`%APPDATA%\LiSteward\backups\hosts\`
- 文件命名：`hosts_backup_YYYYMMDD_HHMMSS.txt`

**备份触发时机**：
1. 每次写入 Hosts 文件前自动备份
2. 用户手动触发备份

**备份保留策略**：
- 默认保留最近 30 个备份
- 超过限制时自动删除最旧备份（可配置）

**为什么**：
- 自动备份防止用户忘记
- 时间戳命名方便识别和恢复
- 限制数量防止占用过多磁盘空间

### D4: 方案管理

**方案存储位置**：
- `%APPDATA%\LiSteward\profiles\hosts\`
- 文件命名：`<方案名称>.json`

**方案内容**：
```json
{
  "name": "开发环境",
  "entries": [
    {"ip": "127.0.0.1", "domain": "dev.example.com", "comment": "开发服务器", "enabled": true},
    {"ip": "192.168.1.100", "domain": "api.dev.local", "comment": "API 服务", "enabled": true}
  ],
  "created_at": "2025-12-23T10:00:00Z",
  "updated_at": "2025-12-23T15:30:00Z"
}
```

**方案操作**：
- 保存：序列化当前 Hosts 条目 → JSON 文件
- 加载：读取 JSON 文件 → 应用到系统 Hosts 文件
- 切换：加载目标方案 + 自动备份当前配置

### D5: 验证逻辑

**IP 地址验证**：
- IPv4：使用正则表达式 `^(\d{1,3}\.){3}\d{1,3}$` + 范围检查（0-255）
- IPv6：使用 Go 标准库 `net.ParseIP()`

**域名验证**：
- 正则表达式：`^([a-zA-Z0-9]([a-zA-Z0-9\-]{0,61}[a-zA-Z0-9])?\.)+[a-zA-Z]{2,}$`
- 允许本地域名：`localhost`, `*.local`

**为什么**：
- 防止格式错误导致 Hosts 文件失效
- 提前反馈错误，提升用户体验

### D6: 并发控制

**问题**：虽然是单用户应用，但系统可能有其他进程修改 Hosts 文件。

**解决方案**：
- 使用文件互斥锁（`sync.Mutex` 在应用内部）
- 读取前检查文件修改时间戳，如有外部修改则提示用户
- 写入使用原子性操作（临时文件 + 重命名）

## 风险 / 权衡

### R1: 权限不足
**风险**：应用未以 Admin 权限运行，无法写入 Hosts 文件  
**缓解**：
- 启动时检查权限
- 提示用户以管理员身份运行
- 在应用清单中标记 `requireAdministrator`

### R2: Hosts 文件被其他程序锁定
**风险**：防病毒软件或其他工具锁定 Hosts 文件  
**缓解**：
- 捕获文件访问错误，友好提示用户
- 提供"重试"选项
- 建议用户检查防病毒设置

### R3: 格式兼容性
**风险**：现有 Hosts 文件包含特殊格式或注释  
**缓解**：
- 解析时保留无法识别的行（作为注释保存）
- 写入时保持原有格式
- 提供"预览"功能，让用户确认变更

### R4: 数据丢失
**风险**：写入失败或应用崩溃导致 Hosts 文件损坏  
**缓解**：
- 每次写入前自动备份
- 使用原子性写入（临时文件）
- 提供恢复功能

## 迁移计划

由于这是新增功能，无需数据迁移。

**首次运行**：
1. 创建应用数据目录结构
2. 读取系统 Hosts 文件并展示
3. 提示用户创建第一个备份

## 待决问题

1. **DNS 缓存刷新**：是否在应用内提供 `ipconfig /flushdns` 快捷按钮？
   - 决策：暂不实现，在 UI 中提示用户手动刷新

2. **方案冲突检测**：加载方案时是否检测 IP 冲突（同一域名多个 IP）？
   - 决策：第一版不实现，可在后续版本添加

3. **实时生效**：Hosts 文件修改后是否立即生效？
   - 决策：依赖操作系统，应用不做额外处理

4. **界面布局**：采用表格视图还是卡片视图？
   - 决策：使用表格视图（更适合编辑大量条目）
