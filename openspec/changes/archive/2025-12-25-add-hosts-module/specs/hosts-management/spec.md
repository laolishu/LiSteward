# Hosts 文件管理规范

## 目的

为 LiSteward 应用提供统一的 Hosts 文件管理功能，使开发者能够在不同的开发、测试和生产环境间便捷切换，并通过方案管理和自动备份机制确保系统配置的安全性和可靠性。

## 新增需求

### 需求：Hosts 文件读取

系统必须能够读取 Windows 系统 Hosts 文件并解析为结构化数据。

#### 场景：成功读取 Hosts 文件

- **当** 用户打开 Hosts 管理模块
- **那么** 系统读取 `C:\Windows\System32\drivers\etc\hosts` 文件
- **并且** 解析文件内容为条目列表
- **并且** 在界面中展示所有条目

#### 场景：解析启用的条目

- **当** Hosts 文件包含行 `127.0.0.1 localhost # 本地回环`
- **那么** 解析为：IP=`127.0.0.1`, 域名=`localhost`, 注释=`本地回环`, 启用=`true`

#### 场景：解析禁用的条目

- **当** Hosts 文件包含行 `# 192.168.1.100 dev.local # 开发服务器`
- **那么** 解析为：IP=`192.168.1.100`, 域名=`dev.local`, 注释=`开发服务器`, 启用=`false`

#### 场景：忽略空行和纯注释

- **当** Hosts 文件包含空行或纯注释行
- **那么** 系统忽略这些行，不创建条目

#### 场景：权限不足

- **当** 应用未以 Administrator 权限运行
- **那么** 显示错误提示："需要管理员权限才能访问 Hosts 文件"
- **并且** 提供"以管理员身份重启"选项

---

### 需求：Hosts 文件写入

系统必须能够将修改后的条目写入 Hosts 文件。

#### 场景：成功写入 Hosts 文件

- **当** 用户点击"保存"按钮
- **那么** 系统自动备份当前 Hosts 文件
- **并且** 将条目列表转换为标准 Hosts 文件格式
- **并且** 写入到 `C:\Windows\System32\drivers\etc\hosts`
- **并且** 显示成功提示

#### 场景：生成启用条目

- **当** 条目为：IP=`192.168.1.100`, 域名=`api.dev.local`, 注释=`API服务`, 启用=`true`
- **那么** 生成行：`192.168.1.100    api.dev.local    # API服务`

#### 场景：生成禁用条目

- **当** 条目为：IP=`10.0.0.5`, 域名=`old.server.com`, 启用=`false`
- **那么** 生成行：`# 10.0.0.5    old.server.com`

#### 场景：写入失败处理

- **当** 写入 Hosts 文件失败（如被其他程序锁定）
- **那么** 显示错误提示："Hosts 文件被占用，请关闭防病毒软件或其他相关程序后重试"
- **并且** 提供"重试"按钮

---

### 需求：条目验证

系统必须验证 IP 地址和域名格式，防止无效配置。

#### 场景：验证有效的 IPv4 地址

- **当** 用户输入 IP 地址 `192.168.1.1`
- **那么** 验证通过，允许保存

#### 场景：拒绝无效的 IPv4 地址

- **当** 用户输入 IP 地址 `999.999.999.999`
- **那么** 显示错误："无效的 IPv4 地址"
- **并且** 禁止保存

#### 场景：验证有效的域名

- **当** 用户输入域名 `api.example.com`
- **那么** 验证通过

#### 场景：支持 localhost

- **当** 用户输入域名 `localhost`
- **那么** 验证通过（允许特殊域名）

#### 场景：拒绝空白域名

- **当** 用户域名字段为空
- **那么** 显示错误："域名不能为空"

---

### 需求：条目管理

系统必须支持添加、删除、编辑和启用/禁用 Hosts 条目。

#### 场景：添加新条目

- **当** 用户填写 IP=`127.0.0.1`, 域名=`test.local`, 注释=`测试`
- **并且** 点击"添加"按钮
- **那么** 新条目添加到列表末尾
- **并且** 条目默认为启用状态

#### 场景：删除条目

- **当** 用户选中某条目
- **并且** 点击"删除"按钮
- **那么** 显示确认对话框："确定要删除此条目吗？"
- **并且** 用户确认后，从列表中移除该条目

#### 场景：编辑条目

- **当** 用户双击某条目或点击"编辑"按钮
- **那么** 打开编辑对话框，显示当前值
- **并且** 用户修改后点击"保存"
- **那么** 更新条目内容

#### 场景：切换条目启用状态

- **当** 用户点击条目的"启用/禁用"开关
- **那么** 切换条目的 `enabled` 状态
- **并且** 界面立即反映变更（禁用条目显示为灰色或带删除线）

---

### 需求：自动备份

系统必须在每次修改 Hosts 文件前自动创建备份。

#### 场景：写入前自动备份

- **当** 用户点击"保存"按钮
- **那么** 系统先将当前 Hosts 文件复制到备份目录
- **并且** 备份文件命名为 `hosts_backup_YYYYMMDD_HHMMSS.txt`
- **并且** 然后执行写入操作

#### 场景：备份成功通知

- **当** 备份创建成功
- **那么** 在界面底部显示："已自动备份当前配置"（3秒后自动消失）

#### 场景：备份失败处理

- **当** 备份创建失败（如磁盘空间不足）
- **那么** 显示错误："备份失败，操作已取消"
- **并且** 中止写入操作，保持原 Hosts 文件不变

---

### 需求：备份管理

系统必须允许用户查看、恢复和删除备份。

#### 场景：列出所有备份

- **当** 用户打开"备份管理"界面
- **那么** 显示所有备份文件列表
- **并且** 每个备份显示：时间戳、文件大小
- **并且** 按时间倒序排列（最新的在最上面）

#### 场景：从备份恢复

- **当** 用户选中某个备份
- **并且** 点击"恢复"按钮
- **那么** 显示确认对话框："恢复此备份将覆盖当前 Hosts 文件，是否继续？"
- **并且** 用户确认后，将备份文件内容写入 Hosts 文件
- **并且** 重新加载当前条目列表

#### 场景：删除备份

- **当** 用户选中某个备份
- **并且** 点击"删除"按钮
- **那么** 显示确认对话框
- **并且** 用户确认后，删除备份文件

#### 场景：自动清理旧备份

- **当** 备份数量超过 30 个
- **那么** 系统自动删除最旧的备份文件
- **并且** 保留最近的 30 个备份

---

### 需求：方案管理

系统必须支持保存、加载和管理多个 Hosts 配置方案。

#### 场景：保存当前配置为方案

- **当** 用户点击"保存方案"按钮
- **那么** 显示输入对话框："请输入方案名称"
- **并且** 用户输入名称如 `开发环境`
- **那么** 将当前条目列表保存为 JSON 文件
- **并且** 显示成功提示："方案 '开发环境' 已保存"

#### 场景：方案名称重复

- **当** 用户输入的方案名称已存在
- **那么** 显示确认对话框："方案 '开发环境' 已存在，是否覆盖？"
- **并且** 用户确认后覆盖原方案

#### 场景：加载方案

- **当** 用户从方案选择器中选择 `测试环境`
- **那么** 显示确认对话框："加载方案将替换当前配置，是否继续？"
- **并且** 用户确认后，读取方案文件
- **并且** 应用方案条目到 Hosts 文件
- **并且** 刷新界面显示

#### 场景：列出所有方案

- **当** 用户打开方案选择器
- **那么** 显示所有已保存的方案列表
- **并且** 显示每个方案的名称和创建时间

#### 场景：删除方案

- **当** 用户在方案列表中点击"删除"按钮
- **那么** 显示确认对话框
- **并且** 用户确认后，删除方案 JSON 文件

---

### 需求：搜索和过滤

系统必须支持搜索和过滤 Hosts 条目。

#### 场景：按域名搜索

- **当** 用户在搜索框输入 `dev`
- **那么** 只显示域名包含 `dev` 的条目
- **例如**：`dev.local`, `api.dev.com`

#### 场景：按 IP 搜索

- **当** 用户在搜索框输入 `192.168`
- **那么** 只显示 IP 包含 `192.168` 的条目

#### 场景：清空搜索

- **当** 用户清空搜索框
- **那么** 显示所有条目

#### 场景：过滤启用/禁用条目

- **当** 用户选择"仅显示启用"过滤器
- **那么** 只显示 `enabled=true` 的条目

---

### 需求：用户反馈

系统必须提供清晰的操作反馈和状态提示。

#### 场景：操作成功提示

- **当** 用户完成保存、加载等操作
- **那么** 在界面顶部显示绿色成功提示
- **并且** 3秒后自动消失

#### 场景：操作失败提示

- **当** 操作失败（如权限不足、文件被锁定）
- **那么** 显示红色错误提示
- **并且** 说明具体原因和建议解决方案

#### 场景：加载状态指示

- **当** 执行耗时操作（如读取大型 Hosts 文件）
- **那么** 显示加载动画或进度条
- **并且** 禁用操作按钮防止重复提交

#### 场景：确认对话框

- **当** 用户执行危险操作（删除、覆盖）
- **那么** 显示确认对话框
- **并且** 清晰说明操作后果
- **并且** 提供"确定"和"取消"按钮
