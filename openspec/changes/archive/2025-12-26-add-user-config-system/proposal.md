# 变更：添加用户配置系统

## 为什么

LiSteward 应用需要持久化保存用户配置和 Hosts 配置方案，当前的实现存在以下问题：

- **配置管理分散**：语言配置存储在 `config/app.json`，方案存储在内存中，没有统一的用户配置体系
- **方案持久化缺失**：Hosts 方案数据未保存到文件系统，应用重启后方案丢失
- **配置目录结构不清晰**：应用数据目录结构不合理，缺乏明确的配置和数据分组
- **跨应用配置难度大**：当前结构不利于未来扩展其他功能的配置需求

## 变更内容

### 核心功能

#### 1. 定义用户配置系统

应用必须建立统一的用户配置管理体系，包括：

- **配置目录结构**：必须在 `%APPDATA%/LiSteward/` 下建立标准化目录
- **配置文件格式**：必须统一使用 JSON 格式存储用户配置
- **配置持久化**：必须支持读取和保存用户配置到本地文件
- **配置兼容性**：必须确保后续新增配置项时的向后兼容性

#### 2. 用户配置文件

应用必须创建用户配置文件 `config/user.json`，包含：

- **语言设置**（从 `config/app.json` 迁移）
- **其他用户偏好**（为未来扩展预留）

文件结构示例：
```json
{
  "language": "zh-CN",
  "theme": "dark"
}
```

#### 3. Hosts 方案文件存储

应用必须将 Hosts 配置方案持久化到文件系统：

- **存储位置**：`%APPDATA%/LiSteward/data/profiles/hosts/` 目录
- **文件命名规则**：每个方案必须对应一个 JSON 文件，命名格式 `host_<name>.json`
  - 示例：`host_work.json`、`host_development.json`
- **文件结构**：必须遵循 `HostsProfile` 模型
- **自动加载**：应用启动时必须自动从目录加载所有方案

#### 4. 配置目录设计

系统必须采用统一的应用数据目录结构：

```
%APPDATA%/LiSteward/
├── config/
│   ├── app.json          # 应用配置（内置）
│   └── user.json         # 用户配置（新增）
└── data/
    ├── backups/
    │   └── hosts/        # Hosts 文件备份
    └── profiles/
        └── hosts/        # Hosts 配置方案（新增）
```

### 迁移计划

- **向后兼容**：应用启动时必须检查旧配置，如存在则迁移
- **语言设置迁移**：必须将 `config/app.json` 的 `language` 字段迁移到 `config/user.json`
- **方案迁移**：必须将内存中的方案数据迁移到文件系统

## 验收标准

- [ ] 用户配置系统正确初始化
- [ ] `config/user.json` 文件正确创建和读取
- [ ] 语言配置正确迁移到用户配置文件
- [ ] Hosts 方案正确保存为单个文件
- [ ] 方案文件命名规范正确（`host_` 前缀）
- [ ] 应用启动时自动加载所有方案
- [ ] 旧配置兼容性测试通过
- [ ] 后续配置项扩展不影响现有配置
