# Hosts 权限问题 - 快速修复指南

## 🔴 问题现象

添加/编辑/删除 Hosts 条目时出现：
```
添加失败: 更新 Hosts 文件失败: rename ... Access is denied
```

## ✅ 立即解决方案

### 方法 1: 以管理员身份运行（最常见的解决方法）
1. **退出程序**
2. **右键点击程序** → "以管理员身份运行"
3. **重试添加/编辑操作**

### 方法 2: 关闭干扰程序
如果仍有问题，关闭以下程序：
- ✅ 任何正在编辑 Hosts 文件的编辑器（记事本、VS Code 等）
- ✅ 防病毒软件（临时禁用）
- ✅ DNS 工具软件
- ✅ VPN 工具

然后重试操作。

### 方法 3: 修复已提交
此问题已在后端进行修复：
 修改文件: `internal/hosts/service.go`

## 📋 检查清单

运行程序前，确保：
- [ ] 以 **管理员身份** 运行
- [ ] Hosts 文件 **没有被编辑器打开**
- [ ] **防病毒软件** 允许修改 Hosts 文件
- [ ] 程序已经 **重新编译**（如果进行了代码修复）

## 🔧 如果问题仍然存在

1. **打开 PowerShell (管理员)**
2. **运行这些诊断命令:**
   ```powershell
   # 检查权限
   whoami /priv | findstr SeManageVolumePrivilege
   
   # 检查文件权限
   icacls "C:\Windows\System32\drivers\etc\hosts"
   ```

3. **查看输出:**
   - 如果看到 `SeManageVolumePrivilege: Enabled` → 权限正常
   - 如果没看到或显示 Disabled → 需要以管理员运行

## 🆘 技术细节（可选）

**根本原因:**
- Windows 系统对 Hosts 文件的文件重命名操作有限制
- 即使有管理员权限，重命名也可能因文件占用而失败

**修复方案:**
- 改为直接覆盖（`os.WriteFile`）而不是重命名
- 这种方式在 Windows 上更可靠

**影响范围:**
- ✅ 添加条目
- ✅ 编辑条目
- ✅ 删除条目
- ✅ 启用/禁用条目
- ✅ 恢复备份
