## 新增需求

### 需求：系统托盘集成与窗口控制

应用必须提供系统托盘集成功能，允许用户将应用最小化到 Windows 系统托盘，并通过托盘菜单快速控制窗口显示/隐藏。用户必须能在设置中启用或禁用此功能；启用后，关闭按钮（X）必须最小化应用到托盘而非退出。

#### 场景：启用托盘最小化功能

- 前置条件：应用已安装并运行。
- 操作：用户在 Settings > 系统托盘 中启用"最小化到托盘"复选框。
- 期望结果：配置被保存，应用在系统托盘中显示图标。之后点击窗口关闭按钮（X）应将应用最小化到托盘而非退出。

#### 场景：通过托盘菜单显示应用

- 前置条件：托盘最小化功能已启用，应用最小化到托盘。
- 操作：用户点击系统托盘中的应用图标或右键选择菜单中的"显示"选项。
- 期望结果：应用窗口立即显示在前台。

#### 场景：通过托盘菜单隐藏应用

- 前置条件：应用窗口可见，托盘功能已启用。
- 操作：用户点击托盘图标或右键选择菜单中的"隐藏"选项。
- 期望结果：应用窗口隐藏，仅托盘图标可见。

#### 场景：禁用托盘最小化功能

- 前置条件：托盘最小化功能已启用。
- 操作：用户在 Settings 中禁用"最小化到托盘"复选框。
- 期望结果：配置被保存，之后点击关闭按钮时应用正常退出（不最小化到托盘）。

### 需求：全局快捷键支持

应用必须支持用户配置全局快捷键（如 Ctrl+Alt+L），在任何时刻按下该快捷键时可唤醒隐藏的应用窗口或隐藏可见的窗口。快捷键功能必须可独立启用/禁用，并必须支持自定义。

#### 场景：配置全局快捷键

- 前置条件：应用已安装并运行。
- 操作：用户在 Settings > 系统托盘 中启用"启用全局快捷键"并在快捷键输入框中输入快捷键（如 "ctrl+alt+l"）。
- 期望结果：快捷键配置被保存，应用注册该全局快捷键。用户可在系统任何地方按下该快捷键。

#### 场景：通过全局快捷键唤醒隐藏的应用

- 前置条件：应用已隐藏或最小化，全局快捷键已配置并启用。
- 操作：用户在系统任何地方按下配置的快捷键（如 Ctrl+Alt+L）。
- 期望结果：应用窗口立即显示在前台，获得焦点。

#### 场景：通过全局快捷键隐藏可见的应用

- 前置条件：应用窗口可见，全局快捷键已配置并启用。
- 操作：用户按下配置的快捷键。
- 期望结果：应用窗口隐藏或最小化（根据"托盘最小化"功能是否启用）。

#### 场景：修改全局快捷键

- 前置条件：已配置的快捷键为 Ctrl+Alt+L。
- 操作：用户在 Settings 中修改快捷键为 Shift+Alt+H 并保存。
- 期望结果：旧快捷键失效，新快捷键生效。应用应正确注销旧快捷键并注册新快捷键。

#### 场景：禁用全局快捷键

- 前置条件：全局快捷键已启用。
- 操作：用户在 Settings 中禁用"启用全局快捷键"复选框。
- 期望结果：快捷键被注销，用户无法通过快捷键唤醒应用。

### 需求：托盘菜单与操作

应用的系统托盘菜单必须提供清晰的操作选项，允许用户快速访问常用功能。

#### 场景：托盘菜单包含标准选项

- 期望结果：托盘右键菜单必须包含以下选项：
  - "显示"（或"打开"）：显示应用窗口。
  - "隐藏"：隐藏应用窗口。
  - "设置"：打开 Settings 页面。
  - "退出"：安全退出应用。

#### 场景：点击托盘图标切换窗口状态

- 前置条件：应用已安装，托盘功能启用。
- 操作：用户直接左键点击托盘图标（不打开菜单）。
- 期望结果：如果窗口隐藏则显示；如果窗口可见则隐藏。

### 需求：配置持久化与恢复

用户的托盘与快捷键配置必须保存到用户 config 文件，应用重启后必须恢复用户偏好设置。

#### 场景：配置持久化到用户 config

- 前置条件：用户在 Settings 中修改了托盘或快捷键配置。
- 操作：用户点击"保存"或配置自动保存。
- 期望结果：配置被写入用户 config 文件（如 `data/config/user.json`），包含 `tray_enabled`、`hotkey_enabled`、`hotkey` 等字段。

#### 场景：重启后恢复配置

- 前置条件：用户已配置了托盘与快捷键，然后关闭应用。
- 操作：用户重新启动应用。
- 期望结果：应用从用户 config 中加载配置，恢复之前的托盘与快捷键设置。托盘图标应显示，快捷键应生效。

### 需求：国际化支持

托盘菜单、Settings UI 与提示文本必须支持中文与英文。

#### 场景：中文界面下的托盘菜单

- 前置条件：应用语言设置为中文（zh-CN）。
- 期望结果：托盘右键菜单必须显示中文文本："显示"、"隐藏"、"设置"、"退出"。

#### 场景：英文界面下的托盘菜单

- 前置条件：应用语言设置为英文（en-US）。
- 期望结果：托盘右键菜单必须显示英文文本："Show"、"Hide"、"Settings"、"Quit"。

### 需求：错误处理与用户提示

若快捷键注册失败或托盘操作失败，应用必须向用户显示清晰的错误提示，允许重试或采取替代措施。

#### 场景：快捷键注册失败

- 前置条件：用户输入一个已被其他应用占用的快捷键（如 Win+X）。
- 操作：用户尝试保存该快捷键配置。
- 期望结果：后端返回错误，前端显示提示："快捷键已被占用，请选择其他快捷键"，并允许用户重新输入。

#### 场景：快捷键格式验证

- 前置条件：用户在快捷键输入框中输入无效格式（如 "invalid"）。
- 操作：用户尝试保存配置。
- 期望结果：前端或后端验证快捷键格式，显示错误提示："快捷键格式不正确，请使用 Ctrl+Alt+L 的格式"。

### 需求：跨平台预留设计

虽然当前仅实现 Windows 支持，应用的架构必须为将来的 macOS 与 Linux 扩展留出接口与抽象。

#### 场景：平台特定实现的可测试性

- 期望结果：`TrayManager` 与 `HotKeyManager` 必须为接口，Windows 实现（`tray_windows.go`、`hotkey_windows.go`）应在构建时单独编译（使用 `//go:build windows` 标签）。
- 这样便于将来为 macOS 与 Linux 添加具体实现（`tray_darwin.go`、`hotkey_linux.go` 等）。
